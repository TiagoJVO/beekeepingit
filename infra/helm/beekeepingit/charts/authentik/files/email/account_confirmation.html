{# BeekeepingIT account-confirmation email (#648, FR-ONB-1, FR-UX-1, NFR-SEC-1, NFR-I18N-1). WHAT THIS OVERRIDES, AND HOW. Authentik's Django settings put the configurable email template dir FIRST in the template search path — `TEMPLATES[0]["DIRS"] = [CONFIG.get("email.template_dir")]` (root/settings.py), and Django's `DIRS` loader runs before the per-app loader. So a file at `/email/account_confirmation.html` is served INSTEAD of `authentik/stages/email/templates/email/account_confirmation.html`, with no change to the email stage: the blueprint keeps pointing at the same template NAME (`template: email/account_confirmation.html`). That is deliberate — if this file is not mounted, the built-in template still renders and mail still goes out. The failure mode of the override is "unbranded email", never "no email". The mount itself is NOT in this repo. This chart ships the file as a ConfigMap (`beekeepingit-authentik-email-templates`, templates/email-templates-configmap.yaml) and sets `AUTHENTIK_EMAIL__TEMPLATE_DIR`; the Authentik workload is an external Flux HelmRelease in the beekeepingit-gitops repo (ADR-0012/ADR-0016), so mounting that ConfigMap on the server + worker is a change there — see the PR's "Before merge" list. NO `{% extends %}`. Upstream's template extends `email/base.html`, whose block names are internal API that moves between releases; extending it would also inherit the authentik logo and the "Powered by authentik" footer this issue exists to remove. Self-contained costs a few more lines and cannot silently lose its body on a version bump. NO IMAGES. Gmail and Outlook block `data:` image URIs outright, and this deployment has no public, stable host for a remote logo (the PWA origin is per-environment and the recipient may open the mail with no session). So the wordmark is TEXT in the brand's display serif — it renders identically everywhere, including a text-only client. i18n (NFR-I18N-1, D-34, #412). Every visible string is one of authentik's OWN msgids, copied byte-for-byte from the template this replaces, so the shipped `pt_PT` catalog keeps translating them; the send activates the request's negotiated language (`pt-PT` -> `pt` -> the `pt_PT` catalog, verified in the container on #412). Introducing a new English string here would be untranslated text on a page that is currently translated — do not. COLOURS are tokens from client/lib/theming/brand_tokens.dart, the app's light scheme: cream #F6F3EC ground, paper #FFFFFF card, ink #2B2438 body, honey #F0A81F primary fill with onHoney #3A2E14 on it (6.5:1), muted #524B60 secondary text, hairline #E7E1D3 rules. Inline styles only — email clients strip
